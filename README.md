# Legal Metrology Compliance Backend

Backend API and Database Foundation for **Legal Metrology (Packaged Commodities) Rules, 2011** inspection system (SIH Problem Statement 26034).

## Architecture Overview

This is a **backend-only** service built with Python and FastAPI, designed to integrate with Supabase (PostgreSQL).

```text
backend/
├── main.py                     # FastAPI application entrypoint & lifecycle
├── routes/
│   ├── __init__.py
│   └── health.py               # Health & DB connectivity check endpoint
├── services/                   # Business & OCR services (future phases)
│   └── __init__.py
├── models/
│   ├── __init__.py
│   ├── enums.py                # Status, severity & validation enums
│   └── entities.py             # SQLAlchemy ORM models (PostgreSQL & SQLite)
├── schemas/
│   ├── __init__.py
│   ├── common.py               # Base Pydantic models & API responses
│   ├── rule.py                 # Rule schemas
│   ├── inspection.py           # Inspection schemas
│   ├── extracted_data.py       # Extracted label data schemas
│   ├── violation.py            # Compliance violation schemas
│   └── health.py               # Health check response schemas
├── rules/                      # Compliance rule engine (future phases)
│   └── __init__.py
├── database/
│   ├── __init__.py
```

## Database Schema (`001_initial_schema.sql`)

### Tables & Relationships

1. **`rules`**: Configurable Legal Metrology compliance rules.
   - `id` (UUID PK), `rule_code` (UNIQUE), `name`, `description`, `field_name`, `required` (BOOL), `validation_type`, `severity` (LOW, MEDIUM, HIGH), `active` (BOOL), timestamps.
2. **`inspections`**: Individual product inspection records.
   - `id` (UUID PK), `image_url`, `status` (`PROCESSING`, `COMPLIANT`, `REVIEW`, `NON_COMPLIANT`, `ERROR`), timestamps.
3. **`extracted_data`**: Structured physical declarations extracted by OCR (1:1 with `inspections`).
   - `id` (UUID PK), `inspection_id` (FK to `inspections.id` ON DELETE CASCADE, UNIQUE), `product_name`, `manufacturer`, `net_quantity`, `mrp`, `date`, `consumer_care`, `extraction_confidence`, timestamps.
4. **`violations`**: Deterministic compliance findings generated by rule engine (1:N with `inspections`).
   - `id` (UUID PK), `inspection_id` (FK to `inspections.id` ON DELETE CASCADE), `rule_id` (FK to `rules.id` ON DELETE RESTRICT), `field_name`, `detected_value`, `status` (`FAIL`, `REVIEW`), `severity`, `message`, timestamp.

### Prototype Seed Rules

* `LM001`: Manufacturer Name & Address Declaration (`manufacturer`, `PRESENT`, `HIGH`)
* `LM002`: Net Quantity Standard Unit Declaration (`net_quantity`, `VALID_QUANTITY`, `HIGH`)
* `LM003`: Maximum Retail Price Declaration (`mrp`, `VALID_PRICE`, `HIGH`)
* `LM004`: Date of Manufacture/Packaging (`date`, `VALID_DATE`, `MEDIUM`)
* `LM005`: Consumer Care Details Declaration (`consumer_care`, `PRESENT`, `HIGH`)

## Setup & Installation

### 1. Environment Setup

Create and activate a Python virtual environment:

```bash
# Windows (PowerShell)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Install Dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure Environment

Copy `.env.example` to `.env` and fill in your Supabase credentials or database URL:

```bash
cp .env.example .env
```

Environment variables:
* `SUPABASE_URL`: Your Supabase Project URL (`https://<project-id>.supabase.co`)
* `SUPABASE_KEY`: Supabase anon or service-role API key
* `DATABASE_URL`: Direct PostgreSQL connection string (or defaults to SQLite for local development)
* `PORT`: Server port (default: `8000`)
* `HOST`: Server bind address (default: `0.0.0.0`)

## Applying Database Migration to Supabase

To apply the schema and seed rules to your Supabase project:

1. Open the [Supabase Dashboard](https://supabase.com/dashboard).
2. Navigate to your project -> **SQL Editor**.
3. Copy the contents of `backend/database/migrations/001_initial_schema.sql`.
4. Run the query to create tables, constraints, indexes, and seed prototype rules.

## Phase 2: Scan Intake & OCR Integration

### API Endpoint
* **`POST /api/v1/inspections/scan`**
  - **Content-Type**: `multipart/form-data`
  - **Parameters**:
    - `image` (File, required): Product label image (`image/jpeg`, `image/png`, `image/webp`, `image/heic`).
    - `ocr_text` (Form, optional): Client-provided OCR text (Scenario A). If omitted, backend invokes PaddleOCR (Scenario B).
    - `product_name`, `manufacturer`, `net_quantity`, `mrp` (Form, optional): Field hints.

### Example Request (cURL)
```bash
curl -X POST "http://localhost:8000/api/v1/inspections/scan" \
  -F "image=@label.jpg" \
  -F "ocr_text=Good Bakes Cookies\nNet Qty: 200g\nMRP: Rs. 50"
```

## Running the Backend

Start the FastAPI application with Uvicorn:

```bash
python -m uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

* **Interactive OpenAPI Docs**: `http://localhost:8000/docs`
* **ReDoc**: `http://localhost:8000/redoc`
* **Health Check**: `http://localhost:8000/health`
